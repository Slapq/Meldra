# Bind WorkSpaces and Profiles to sessions

MetaPi WorkSpace launches create one filesystem directory per conversation under `~/.metapi/workspaces/` by default, and `/new`, `/fork`, and `/clone` create a new directory; fork and clone copy the source WorkSpace before the new session starts. Skills, Extensions, Prompt Templates, Themes, and package resources remain in the current Profile unless the user explicitly selects Current WorkSpace scope, which maps to Pi's project-local `.pi` resources. The active Profile is persisted in session extension metadata, `/resume` restores it, and `/profile` may rebuild the current runtime around the same session and WorkSpace so configuration changes do not require restarting MetaPi. This in-session switch applies only within one Session discovery domain: crossing between ordinary MetaPi Profiles and the reserved `pi` compatibility Profile requires a new explicit launch, so neither side moves, copies, or discovers the other's writable Session files.
