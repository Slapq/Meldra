# Treat MetaPi model access as a user asset and model preferences as Profile choices

> Supersedes the earlier shared-file interpretation of this decision: original Pi and ordinary MetaPi Profiles remain independent after optional migration.

MetaPi will keep model authentication, the MetaPi user's custom provider/model catalog, and model catalog state in MetaPi-owned user storage shared by every ordinary MetaPi Profile. Switching Profiles therefore never requires repeating `/login` or recreating model definitions. Default provider/model, enabled-model scope, and thinking level remain Profile choices because they express how a workflow uses the user's available models rather than what the user is able to access. Existing original Pi model assets may be copied once into empty or explicitly selected MetaPi storage for migration convenience, but MetaPi does not continuously synchronize with, read through to, or write back to original Pi afterward. The reserved `pi` compatibility Profile remains an explicit original-Pi launch and continues to use original Pi state.
